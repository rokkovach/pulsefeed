# Project and container review — October 20, 2026

This review covered the FastAPI app, browser code, both separate model workers, their Runpod/Spark packaging, and the dependency inventories of the published AMD64 images. It produced source fixes, regression tests, clearer code comments and a rebuilt local app image. **The GPU images still have known dependency findings and have not been rebuilt with these fixes.**

GPT-6.1-Sol implementation and independent review were assigned separately. Findings were reproduced where practical, fixed, then reviewed again. GPU/model/runtime pins, stored prompts, live quotas and the operator's database were preserved. No cloud deployment, image publication or real inference was performed.

## Fixes made

| Area | Problem and resulting behavior | Source |
| --- | --- | --- |
| Provider backoff | A large or non-finite `Retry-After` could stall a request. Accepted hints are finite and capped at ten seconds; malformed hints use bounded jitter. Submission remains a single attempt because an uncertain response must not cause duplicate GPU work. | [provider.py](../app/pulsefeed/provider.py) |
| Image retrieval | A provider status call could outlive the intended image-response wait. A thirty-second overall deadline now covers status retries and sleeps, preserves cancellation, and returns a controlled temporary-unavailable response. | [coordinator.py](../app/pulsefeed/coordinator.py) |
| Polling cost | Batch lookup and serialization occurred before the poll allowance was checked. Authentication and rate enforcement now precede that work. | [main.py](../app/pulsefeed/main.py) |
| SQLite cleanup | Deleting expired rate events could scan the entire table because the existing index began with scope/action. A separate timestamp index supports global expiry cleanup. It is created idempotently for existing databases. | [db.py](../app/pulsefeed/db.py) |
| Model-cache loading | A pinned directory name and `trust_remote_code=False` did not authenticate cached routing metadata. Before model loading, both workers now verify SHA-256 values for ten small files from the exact pinned model commits and reject Python files and unsafe cache links. Normal Hugging Face snapshot-to-blob file links remain supported. | [Qwen runtime](../workers/qwen/runtime.py), [FLUX worker](../workers/flux/flux_worker.py) |
| FLUX cleanup | Cleanup failure could leave readiness misleading. The known result and counters are preserved, the worker becomes unready, and queued contenders recheck readiness after acquiring the admission lock. Logs contain the exception class, not arbitrary exception text. | [FLUX worker](../workers/flux/flux_worker.py) |
| Qwen shutdown | Concurrent and signal-reentrant shutdown could close the same pipe twice. Shutdown is protected by a reentrant lock, with pipe ownership marked before closing. | [Qwen runtime](../workers/qwen/runtime.py) |
| Browser recovery | A stalled response body could leave controls or polling stuck. Thirty-second deadlines now cover headers and body reads; navigation/expiry aborts pending work. Unknown submissions retain their idempotency identity, including explicit retries across reloads. | [app.js](../app/pulsefeed/static/app.js) |
| Admin restoration | Browser back/forward restoration could leave refreshes or cooldowns stopped. Usage refresh resumes, drafts survive, and settings cooldowns are calculated from an absolute deadline. | [admin.js](../app/pulsefeed/static/admin.js), [settings.js](../app/pulsefeed/static/settings.js) |
| Text contrast | Muted metadata, usage labels and footer text were too faint in light mode. Their colors now have measured contrast above 4.5:1 against the reviewed backgrounds. | [CSS source](../app/pulsefeed/static/tailwind.input.css) |
| App packaging | The app used an older, tag-only Python base and reinstalled dependencies after source changes. It now pins Python 3.11.17 by digest, installs constrained runtime dependencies before source COPY, and uses a BuildKit download cache. Test packages are absent from the resulting image. | [Dockerfile](../app/Dockerfile) |
| Build context | A denylist could miss newly named private files or artifacts. An explicit runtime-input allowlist now excludes unrelated files, including nested environment files, databases and bytecode. | [.dockerignore](../app/.dockerignore) |

The model-cache checks authenticate the enumerated metadata only. They do **not** hash all model weights, authenticate every tokenizer/template file, or prevent a trusted cache writer from changing files between validation and loading. Keep cache writers restricted, and avoid concurrent cache mutation during startup.

## Dependency and container findings

The app's unchanged 26-package lock returned zero known advisory matches and zero skipped packages in the October 20 query. Python itself was updated from the old 3.11.12 base to the official [3.11.17 security release](https://www.python.org/downloads/release/python-31117/). This does not establish that every OS library in the app image is vulnerability-free.

The worker check used their complete expected inventories and the actual build-time SPDX SBOMs attached to the [October 16 private image digests](runpod-first-deployment.md#published-candidate--october-16-2026). It did not substitute a generic PyPI Torch build for NVIDIA's versions.

The reviewed queue does not start the LMCache transport or expose the embedding/penalty/batched-input prerequisites of the vLLM report. **These numbers overlap the Python results and are not exploit counts.** Confirmed Ubuntu update families include OpenSSL and GnuPG in both images, plus Qwen PackageKit/sudo. Conda binaries, wheel-bundled FFmpeg and embedded RPM metadata have different owners; an `apt` upgrade does not repair all of them. Two embedded AlmaLinux RPM matches used Ubuntu advisory versions and were flagged as cross-distribution candidates.

Focused triage verified six of seven native candidates labeled Critical by Grype against primary sources. Upstream OpenSSL severities differ from those generic Critical labels, with specific CMS/CMP/32-bit/AEAD prerequisites. The Python candidate requires a particular TLS-server callback, not ordinary TLS-client behavior. The remaining FFmpeg candidate needs upstream confirmation. No blanket dismissal of runtime library findings is justified.

The current source closes the reproduced metadata-loading gap. The published images still contain their earlier validators. Selecting a fixed FLUX class alone was insufficient to prevent dynamic local-module loading; the new metadata/file checks are necessary additional safeguards.

## Remaining work before cloud release

1. **Rebuild both workers under new version tags.** The October 16 images do not contain this review's source fixes. Produce new inventories/SBOMs and repeat scans against those exact digests.
2. **Plan and test dependency remediation by layer.** GPU package pins were preserved. OS, Conda and bundled native updates need compatible rebuilt images and real inference checks; this review has not cleared the retained findings for release.
3. **Run target-GPU and native Runpod queue smoke tests.** Spark was unreachable during this session, so updated model-container builds, GPU initialization and inference were not rerun. Earlier Spark results do not validate these new loaders or the AMD64 Blackwell target.
4. **Retain the current scale boundary.** SQLite calls are synchronous. A controlled 200 ms competing writer delayed a nominal 10 ms event-loop task to about 263 ms. Keep write transactions short and one app/coordinator process; moving persistence off the event loop or changing the database requires a separate concurrency design.
5. **Validate runtime isolation and storage ownership.** Images currently retain root execution for their existing volume/vendor setup. A non-root switch must include tested Railway `/data` and Runpod model-cache permissions. Do not expose inherited notebook, Ray or generic vLLM services; verify actual processes and ports on the target.

The review also does not establish cloud cold-start time, sustained throughput, cost, production proxy/cookie behavior, host-driver security or complete model-weight integrity. [Deployment](deployment.md), [operations](operations.md) and the [code walkthrough](code-walkthrough.md) remain the working guides.
